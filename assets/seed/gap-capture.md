# 技能缺口捕捉

命中「技能做不到 / 记成升级需求 / 这是 skill 的问题 / 技能缺口」时加载本文件。禁止未加载就落缺口文。禁止把本文件写成业务需求册。

改 Skill 仍走 `governance/rules/skill-governance.md`（A 出方案，人同意或 B 审）。缺口稿 **不是** AP，**禁止**因记缺口而改 `SKILL.md`。

## 1. 要落盘（明示）

用户明示：技能做不到 / 做不了 / 这是 skill 的问题 / 记成升级需求 / 记成技能缺口。

先写后告知。禁止问「要不要记」。

不要落盘：缺数据、换个文件夹就能做、规则已有只是本轮没加载、口误已纠正、无明示口令的普通不满。

## 2. 落盘前扫描

禁止全文扫包。读根 `VERSION`（或已装 `skill.json` 的 version，禁止猜）+ 按痛点定向读涉及的规则/模板。

- **已包含**该能力：找同指纹旧稿 → `status: deprecated`，`resolved_in_skill: vX.Y.Z`，标题下废弃横幅。用户已删旧稿 → 不动作。
- **未包含**：§3 原位或新建。
- 拿不准 → 按未包含。

## 3. 写哪里

当前工作区（技能所服务的目录）：

```
outputs/skill-gaps/SG-YYYYMMDD-NNN-需求-{短标题}.md
```

`outputs/skill-gaps/` 懒建。禁止写到工作区根上与 `SKILL.md` 平级。禁止写进 `governance/`（开发用，且不进安装包）。

`sg_id`：`SG-{今天}-NNN`。NNN = 当日已有最大号 +1，无则 001。短标题 ≤20 字，来自一句话痛点。

**指纹**：涉及规则路径 + 痛点关键词。同指纹且未并入：原位更新（1～6 按最新事实重写，第 7 节追加一行，复用原文件名）。不存在则新建。用户说另出一版才新开号。

用户说不要记 → 该份 `status: cancelled`，本对话同类不再写。

模板只读本包 `assets/templates/skill-gap-demand.md`。禁止用历史缺口稿当范本。缺节不得落盘。

建议补丁节只列条目，**禁止**写成完整 AP-1～AP-7。

## 4. 告知（强制）

每次落盘或原位后一句话必须含：文件路径 + 本次记录了什么 + 历史迭代是否已在文中。禁止只报路径。废弃时：路径 + 已并入版本。

## 5. 与升级方案

A 出 AP 前：若本目录有 `status=draft` 的稿，必须读并在 AP-1 引用 `sg_id`。没有缺口稿时，人口头需求仍可出 AP。
