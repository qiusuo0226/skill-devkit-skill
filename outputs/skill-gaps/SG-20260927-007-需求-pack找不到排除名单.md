# Skill 升级需求：pack.py 找不到 pack_exclude.py（修复）

> **已并入 v0.11.0**（2026-09-27）。见 `CHANGELOG.md` 0.11.0 段与 `governance/migrations/upgrade-to-0.11.0.md`。

> 一句话痛点：**目标仓改了 pack.ini 的排除名单，打包时被悄悄忽略。**

- **所属 Skill**：skill-devkit
- **Skill 版本**：0.10.1（根 `VERSION`）
- **日期**：2026-09-27
- **状态**：deprecated（已并入 v0.11.0）

## 1. 用户原话

> assets/seed/pack.py 的 `_load_exclude_mod` 去 `here.parents[2]/governance/scripts/pack_exclude.py` 找，但 pack.py 在 governance/pack/ 里，parents[2] 已经是仓库的上一级。效果：pack.ini 的排除改动被悄悄忽略，用内置名单，打印 WARN: pack_exclude.py missing。（主代理转述）

## 2. 期望 vs 实际

| 维度 | 用户期望 | 技能实际 |
|---|---|---|
| 查找路径 | `{仓}/governance/scripts/pack_exclude.py` | `here = Path(__file__).resolve().parent` = `{仓}/governance/pack`；`here.parents[2]` = 仓的上一级 |
| pack.ini 生效 | 改了就生效 | 已实测：目标仓布局下 `pack.ini` 加 `extra_dir`，dry-run 仍打进 `extra_dir/a.md`，stderr 有 WARN |
| 审计 | 能拦下 | 默认 `pack.ini` 时「agree」PASS（内置名单与种子 ini 相同）；改过 `pack.ini` 才 FAIL |

## 3. 现状为何

- 正确写法是 `here.parent / "scripts" / "pack_exclude.py"`（等价 `here.parents[1] / "governance" / "scripts" / …`）。主代理转述的 `here.parents[1] / "scripts"` 按现在 `here` 是目录的写法会指到 `{仓}/scripts/`，同样找不到——已实测。
- 本包自己跑的是 `assets/seed/pack.py`，同目录就有 `pack_exclude.py`，第一个候选命中，所以本包不出错，也测不出来。
- 已受影响：`D:\workspace\skill\personal-graph-skill\governance\pack\pack.py`（实跑 dry-run 出 WARN）。`session-handoff-skill` 的 pack.py 是 0.8 以前的老版本，不读 `pack_exclude.py`，不受这条影响。
- `snapshot_baseline.py`、`audit_release.py` 用 `from pack_exclude import` 同目录导入，不受影响。

## 4. 建议补丁

1. 改种子 `pack.py` 第二个候选路径。
2. audit 加一条：pack.py 必须真的找到 `pack_exclude.py`（不许走内置名单）。
3. 变异用例用非默认 `pack.ini` + 目标仓布局（并入 SG-20260927-003）。
4. `upgrade-to-0.11.0` 写已初始化仓的手工修法。

## 5. 如何复现

1. 在已初始化仓 `governance/pack.ini` 的 `dirs` 加一个真实目录名。
2. `python governance/pack/pack.py --skill-root . --dry-run`：那个目录仍在列表里，stderr 有 `WARN: pack_exclude.py missing`。
