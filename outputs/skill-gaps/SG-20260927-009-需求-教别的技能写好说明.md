## 2. 期望 vs 实际

| 维度 | 用户期望 | 技能实际 |
|---|---|---|
| 说明结构 | 做什么 + 什么时候用 + 用户会说的触发 | `01-init.md` §3 第 6 问、§5 只要求「干什么 + 开口说法」拼成 `__DESCRIPTION__` |
| 语言 | 用用户的语言；要英文时英文在前、中文在后 | 未规定 |
| 长度 | ≤1024 字符 | 未提示；`validate_skill.py` 不查 |
| 撞车 | 与已装技能的触发比对 | 只查同名（§3.1），不查触发重叠 |
| 劝退词 | 不写「用完即走」这类让助手不选的话 | 未提示 |

## 3. 现状为何

0.6.0 起初始化问「别人以后怎么开口」，规则只管收集说法，没有写说明的结构要求。本包自己的 description 也是同一种写法，0.11.1 已改本包，种子与问答未改。

## 4. 建议补丁

1. `01-init.md` §3 第 6 问后加「什么时候用」一句，清单里亮出完整说明。
2. §5 写说明时的结构：做什么 → 什么时候用 → 触发 → 不要用于；用户语言；≤1024 字符。
3. `validate_skill.py` 加 description 长度规则（配变异用例）。
4. 可选：初始化时按 `03-skill-roots.md` 读已装技能的触发，报重叠。

## 5. 如何复现

1. 空文件夹「初始化 skill」，第 6 问跳过。
2. 生成的 description 只有「干什么」一句 + 触发，没有「什么时候用」。
