# Skill 升级需求：升版后分发集旧版本号清零

> **已并入 v0.11.0**（2026-09-27）。见 `CHANGELOG.md` 0.11.0 段与 `governance/migrations/upgrade-to-0.11.0.md`。

> 一句话痛点：**升了版本，分发包里还可能留着上一版号或旧 zip 名。**

## 1. 用户原话

> 升版本之后，扫描分发集（不含 CHANGELOG 和基线）里的上一版版本号 / 旧 zip 名，必须零命中。（主代理转述）

## 2. 期望 vs 实际

| 维度 | 用户期望 | 技能实际 |
|---|---|---|
| 扫描 | 分发集内上一版号、`{name}-Skill-v{上一版}.zip` 零命中 | 无此检查；`sync_version.py` 只改 `skill.json` 与 `SKILL.md` 里的版本 |
| 例外 | CHANGELOG、基线不扫 | — |

## 3. 现状为何

版本号散落在 README、示例、说明里时靠人记得改。实扫本包 0.10.1 分发集找 `0.10.0`：只有 `skill.json` 的 `versionHistory` 命中，这类历史记录也必须排除。

## 4. 建议补丁

1. `validate_skill.py` 加规则：上一版号取 `CHANGELOG.md` 第二个 `## x.y.z` 标题；分发集按 `pack.ini`；排除 `CHANGELOG.md` 与 `skill.json` 的 `versionHistory`。
2. 只有一个版本段（0.1.0 新仓）→ 通过。

## 5. 如何复现

1. 升版后在 README 留一处上一版号。
2. 跑 validate / audit：仍全 PASS。
