# Skill 升级需求：触发词三处一致性检查

> **已并入 v0.11.0**（2026-09-27）。见 `CHANGELOG.md` 0.11.0 段与 `governance/migrations/upgrade-to-0.11.0.md`。

> 一句话痛点：**SKILL.md、README、skill.json 各写一份触发词，改了一处没人发现。**

- **所属 Skill**：skill-devkit
- **Skill 版本**：0.10.1（根 `VERSION`）
- **日期**：2026-09-27
- **状态**：deprecated（已并入 v0.11.0）

---

## 1. 用户原话

> 审计里查触发词一致：validate_skill.py 或 audit_release.py 检查 SKILL.md description 里的触发集合，与 README 的触发/开口段、skill.json description 相同。（主代理转述）

## 2. 期望 vs 实际

| 维度 | 用户期望 | 技能实际 |
|---|---|---|
| 检查 | 三处触发集合不等 → FAIL | `validate_skill.py` 只查 description 非空；`audit_release.py` 不看触发 |
| 本包自身 | 三处一致 | `SKILL.md` 有「触发：…」一段；`README.md` 只有「同义口令：」一行且集合不同（如有「从零写 skill」「脚手架」）；`skill.json` description 无触发段 |
| 已初始化仓 | — | personal-graph、session-handoff 三处都带同一段「触发：…」（初始化把同一段描述写进三处） |

## 3. 现状为何

初始化时三处来自同一段 `__DESCRIPTION__`，之后「改开口说法」只要求改 `SKILL.md`，没有机械比对。

## 4. 建议补丁

1. `validate_skill.py` 加一条规则：取三处的「触发：」段（到句号止），按「、」切分、去空白后比集合。
2. 三处都没有该段 → 通过（一致地没有）；只要有一处有 → 三处必须都有且相等。
3. 本包自身要补 README 与 `skill.json` description 的触发段（`skill.json` 属核心契约）。

## 5. 如何复现

1. 在已初始化仓只改 `SKILL.md` description 的触发词。
2. 跑 `governance/scripts/audit_release.py`：仍全 PASS。
