# Skill 升级需求：检查器单点变异自测

> **已并入 v0.11.0**（2026-09-27）。见 `CHANGELOG.md` 0.11.0 段与 `governance/migrations/upgrade-to-0.11.0.md`。

> 一句话痛点：**检查规则写错了也全绿，没有用例证明每条规则真能抓到它该抓的错。**

- **所属 Skill**：skill-devkit
- **Skill 版本**：0.10.1（根 `VERSION`）
- **日期**：2026-09-27
- **状态**：deprecated（已并入 v0.11.0）

## 1. 用户原话

> 检查器的变异自测：validate / audit / pack 排除的每一条规则，都配一个单点变异用例，必须被那一条规则抓到；通过 run_smoke.py 或 audit 强制。（主代理转述）

## 2. 期望 vs 实际

| 维度 | 用户期望 | 技能实际 |
|---|---|---|
| 覆盖 | 每条规则一个变异用例 | `test_validate_skill.py` 只有 3 条反例；audit 规则无反例 |
| 定位 | 必须由「那一条」规则报 FAIL | 现有用例只看退出码或单条 FAIL，不断言其它规则仍 PASS |
| 强制 | 新规则没配用例 → 测试失败 | 无覆盖守卫 |

## 3. 现状为何

`audit_release.py` 的「pack.py and audit load_excludes agree」在 pack.py 找不到 `pack_exclude.py` 时仍 PASS：pack.py 退回内置名单，而种子 `pack.ini` 与内置名单相同，两边自然相等（见 SG-20260927-007）。本包 `tests/test_pack_exclude.py` 的同名测试用的是 `assets/seed/` 同目录布局，那里第一个候选路径就能找到，所以也测不出目标仓布局的错。

## 4. 建议补丁

1. 新测试文件：在临时目录搭一个「目标仓布局」的合格样仓，每个用例只改一处，断言退出码非 0 且 FAIL 的恰好是对应规则名。
2. 覆盖守卫：从合格样仓跑出的规则名清单，每个名字必须有变异用例，否则测试失败。
3. 走 `run_smoke.py` 自动发现；目标仓 audit 本来就跑冒烟。

## 5. 如何复现

1. 按目标仓布局放 `governance/pack/pack.py` 与 `governance/scripts/pack_exclude.py`，`pack.ini` 保持默认。
2. 跑 audit：「agree」PASS，但 stderr 有 `WARN: pack_exclude.py missing`。
