## 这版改了什么

- **效果核对**：人说「A 已经升级完毕，检查开发仓实际升级效果」时，只回复三栏编号清单（满足 / 未满足 / 方案外）。一条方案行一个编号。格式在 `governance/templates/upgrade-effect.md`。核对人不改文件。
- **寿命**：发版前写出的核对单，与方案一起删除，结论行写入当版回归报告。发版后才写出的，当次补进该版回归报告后删除。
- **本包**：对这些口令停止，请人换到目标技能文件夹。
- **新初始化 / 新收编**：拷贝表多一行，自带上述模板和规则。

## 使用者要做什么

- [x] 无需迁移工作区
- [ ] 要用新核对：用新 zip / 新目录替换已安装的本包
- [ ] 已用 0.9.x 及更早初始化过的仓**不会**自动长出核对单。要此能力：在那个仓单独升级，或手拷本版 `assets/templates/upgrade-effect.md`、`assets/seed/upgrade-dual-agent.md`、`assets/seed/skill-governance.md` 的对应内容。不要对本包说升级
- [ ] 新初始化 / 新收编的仓自带上述能力

## 不兼容说明

无。没人要求核对时，发版步骤与 0.9.0 相同。B 审核方案的做法不变。

## 回滚

`git checkout v0.9.0`。本包对照物是 git tag，不是 `governance/baselines/`。不要在半套 0.10.0 上打补丁。
