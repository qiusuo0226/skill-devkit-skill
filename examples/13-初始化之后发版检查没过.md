# 示例：初始化之后发版检查没过

同意执行之后、安装包打出来之前，助手必须跑一遍发版检查。没过就停，先修，不会留下坏包。

检查对的是技能文件夹里这些东西是否一致（你不必自己跑命令，但要知道它在盯什么）：

| 它盯什么 | 人话 |
|---|---|
| 根目录 `VERSION` | 版本号只认这一份 |
| `skill.json` 里的 `version` | 必须和 `VERSION` 同一个号 |
| `CHANGELOG.md` 有 `## 0.2.0` 这种标题 | 这一版改了什么已经写上 |
| 技能说明开头的名字和描述 | 不能空 |
| 技能正文点到的 `references/` 文件 | 文件得真的在 |
| `governance/baselines/0.2.0/` 存在 | 有对照底稿，以后能回滚 |
| 将打进 zip 的文件里没有 `governance/`、`.git/`、`AGENTS.md` | 开发用的说明不进安装包 |
| `governance/planning/upgrade-plan-v0.2.0.md` 不应还在 | 发版后方案要删掉，内容已固化 |

> 假例子：林夏让打包，检查发现 `VERSION` 是 0.2.0，说明里还没有这一版的标题。

---

**你**

> 打一份安装包。

**助手**

> 发版检查没过：`VERSION` 是 0.2.0，但 `CHANGELOG.md` 里没有 `## 0.2.0` 这一段。
>
> 先补这一处。过了再打 `meeting-notes-Skill-v0.2.0.zip`。不会把没过检查的包留下。

**你**

> 改到对上，再打包。

**助手**

> 检查过了。安装包在这个文件夹根上。没有往远程推。

---

只想看包里有什么、先不落盘：

```text
先预览安装包，先别写成文件。
```

预览时助手会列出将打进包的路径（不超过二十条作样本），并点名：**没有** `governance/`、`.git/`、`AGENTS.md`。

---

## 你可以照着说

```text
打一份安装包。
发版检查一下。
先预览安装包，先别写成文件。
```
